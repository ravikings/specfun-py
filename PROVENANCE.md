# Provenance

Every `.f` file in `services/specfun/native/` was fetched from netlib
`specfun` on 2026-09-22:

| File | URL |
|---|---|
| gamma.f, algama.f, psi.f, daw.f, ei.f, erf.f, i0.f, i1.f, k0.f, k1.f, ren.f | https://www.netlib.org/specfun/<stem> |

Upstream listing: https://www.netlib.org/specfun/ (Zhang & Jin,
*Computation of Special Functions*, Wiley 1996; ACM TOMS Algorithm 759).

SHA-256 of every file as packaged was recorded by `nativegate golden
record` in `services/specfun/golden.json` at bind time; any edit that
changes a source file changes the pinned hash, and a rebuild that
changes an answer fails the golden check.

## The one transformation

Upstream marks machine-constant and arithmetic dialect by commenting
every line in both dialects:

```fortran
CS    REAL FUNCTION GAMMA(X)
CD    DOUBLE PRECISION FUNCTION DGAMMA(X)
```

Upstream's wrapper script comments out one prefix to select a dialect.
We made the choice static (DOUBLE PRECISION): `CS` lines were commented
further (`CS` -> `C `) and `CD` prefixes were stripped to two blank
columns. No arithmetic, constant, or control-flow text was altered;
this is why the file names in native/ are the upstream stems.

## What was NOT touched by hand

Fortran: yes, only the prefix transformation above. Everything else in
this tree — bindings, CMakeLists.txt, the Python package, the pytest
suite, golden.json — was generated by nativegate 0.1.0 and is
regenerable:

```bash
cd services/specfun && python -m nativegate generate specfun
```
